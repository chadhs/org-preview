#+title: Org Preview release information

* Release policy
Each push to =main= publishes a new minor release after both platform checks
pass. The first version is =0.1.0=, followed by =0.2.0=, =0.3.0=, and so on.
The GitHub release page contains the exact version, changes, downloads,
and checksums. Pull requests do not publish releases.

* A live reader for Org files
Org Preview opens local =.org= files and refreshes the document when you
save in your editor. It runs on macOS and Linux without requiring Emacs,
an account, or a cloud service.

The application includes:
- Native file picking, drag and drop, and command-line opening.
- Live updates after normal saves, atomic saves, and deletion/recreation.
- An outline, document search, read-only source view, zoom, and themes.
- Headings, emphasis, tasks, tags, lists, checkboxes, tables, and code blocks.
- HTTP/HTTPS/mailto links and common internal heading links.
- An Org heading icon and Linux desktop entries with window matching,
  searchable keywords, Org MIME types, and local file-URL handling.

Document code and embedded HTML never execute. The renderer is sandboxed,
and documents cannot load remote resources. Web links open in your browser;
mail links open your mail client. No telemetry is included.

* Downloads
Replace =VERSION= below with the version shown on the GitHub release page.

| Platform                 | Package                          |
|--------------------------+----------------------------------|
| macOS, Apple Silicon     | Org Preview-VERSION-arm64.dmg       |
| macOS, Apple Silicon     | Org Preview-VERSION-arm64-mac.zip   |
| Linux, x86_64            | Org Preview-VERSION.AppImage        |
| Linux, x86_64            | org-preview-VERSION.tar.gz          |

Builds include a platform-specific =SHA256SUMS-*.txt= file. Compare a
package's SHA-256 with that file before installing. On macOS use
=shasum -a 256 <filename>=; on Linux use =sha256sum <filename>=.

** macOS
Open the DMG and copy Org Preview into Applications, or unzip the ZIP and
move its app into Applications. Keep one installed copy so Finder can pick
the intended app. Launch it and use Open file, or choose Org Preview in
Finder's Open With menu for an =.org= document.

These builds are unsigned and unnotarized. macOS may block the first launch.
The automated build does not exercise Gatekeeper approval for a downloaded,
quarantined artifact. Signing and notarization are outside the current scope.

** Linux, Arch, and Omarchy
The Linux x86_64 builds work on Arch-based systems, including Omarchy.
Native testing used Omarchy 4.0.2 / Hyprland 0.56.2 with Wayland and XWayland.
There is no AUR or pacman package yet.

Make the AppImage executable, then launch it as your normal desktop user.

#+begin_src sh
chmod +x 'Org Preview-VERSION.AppImage'
./Org\ Preview-VERSION.AppImage ~/notes/today.org
#+end_src

If FUSE 2 is unavailable, use extract-and-run or the tar archive:

#+begin_src sh
./Org\ Preview-VERSION.AppImage --appimage-extract-and-run ~/notes/today.org

tar -xzf org-preview-VERSION.tar.gz
./org-preview-VERSION/org-preview ~/notes/today.org
#+end_src

The AppImage includes a desktop entry and icons for desktop integration
tools. The tar archive is portable and does not install a launcher or alter
file associations. Native Wayland and XWayland were tested on Omarchy. You
can choose a display backend with =--ozone-platform=wayland= or
=--ozone-platform=x11=. Sandboxing stays enabled in both modes.

* Known limits
- One document at a time, UTF-8, up to 4 MB.
- This is a reader. Keep editing in your existing editor.
- Org rendering covers the documented subset, not full Emacs export parity.
- Local images and links to other files, math, diagrams, Babel, remote
  includes, agenda features, Quick Look, and automatic updates are excluded.
- Direct FUSE-mounted AppImage launch was not tested on the Omarchy machine,
  which lacks FUSE 2. Extract-and-run and tar execution passed.
- Intel macOS and other architectures have no verified binaries in this release.
- Multiple registered Mac app copies can confuse Finder's generic Open With
  entry. Selecting the exact app works; single-copy installation still needs
  the maintainer's final check.

* Validation and license
The implementation has passed automated checks on macOS and Linux, real
Omarchy Wayland/XWayland testing, and Mac native checks. The user verified
Finder dragging and Mac keyboard shortcuts. CI tests the Mac ZIP application
and validates the extracted AppImage's desktop entry, icon, and sandbox flags.
The README summarizes platform verification. Automated tests stay in the
repository; per-run screenshots and build logs are CI artifacts.

Org Preview and its artwork use BSD-3-Clause. The Org parser, Orga, uses MIT.
Bundled dependencies retain their licenses in =THIRD-PARTY-NOTICES.org=.
