* Result
The development app and the application extracted from the macOS ZIP pass
the sandboxed desktop suite. Native picking and Finder Open With work with
spaces and Unicode. The user verified an actual Finder-to-preview drag.
HTTP and HTTPS links open Safari, and mailto opens Mail with the expected
recipient and subject. The disposable message was discarded without sending.

Testing started at Linux handoff =8dbe922=. The Mac checkout was clean and
fast-forwarded from =c6ce0e7= after inspecting local and remote history.
No Mac changes were discarded. No merge to main or release publication was
performed. Project code remains BSD-3-Clause; Orga remains MIT-licensed.
No dependency or lockfile changes were needed.

Finder lists Org Preview as an available Org viewer, while Emacs remains
the default. The tests did not change the default file handler. Multiple
copies of Org Preview exist on this development Mac. The generic Open With
entry sometimes reached the welcome document instead of the selected file.
Selecting the exact extracted bundle through Open With > Other opened the
requested file. Generic routing between several registered copies remains
an environment-specific limitation; normal installation with one copy was
not tested.

Native coordinate automation reported =noWindowsAvailable= for cross-window
drags, so its failed drag attempts are excluded as application failures.
The user independently dragged the named fixture into the packaged app and
confirmed success. Native keyboard automation was reliable in the development
picker workflow but inconsistent when targeting multiple packaged copies.
The user independently checked the packaged shortcuts and confirmed that
all work. These user confirmations complete the native drag and keyboard
checks that automation could not reliably perform.

* Confirmed defect fixed
macOS keeps the process alive after its last window closes. The prior
=open-file= handler only saved the requested path when no window existed.
Without a separate =activate= event, the file remained invisible. A regression
in the real Electron process reproduced this by closing its last window,
waiting for =closed=, then emitting =open-file=. It timed out waiting for a
new window before the fix.

File requests now create a window when the app is ready and has none.
Startup requests remain queued until readiness. The native Open command
also supports a parentless picker and creates a document window after a
file is selected. Closing a window invalidates unfinished reads so an old
request cannot recreate the previous document watcher after closure.

The smoke suite now checks both no-window paths on macOS, accepts an
=ORG_PREVIEW_EXECUTABLE= path for packaged testing, and uses a disposable
profile for both its primary and secondary CLI processes. CI runs the same
suite against the extracted macOS ZIP in addition to the development app.

* Remaining limits
- Builds are unsigned and unnotarized prototypes. Gatekeeper behavior for a
  downloaded quarantined distribution was not tested or bypassed.
- The DMG passes integrity verification; the ZIP-extracted application was
  the artifact used for full runtime testing.
- The default Electron icon is still present. Branding, signing, and release
  distribution were not added during this test pass.
- Intel macOS hardware was not available. These results cover Apple Silicon.
- Generic Finder routing with multiple registered app copies needs the
  single-installation follow-up described above.
- Existing v0.1 exclusions remain, including editing, Babel execution, remote
  includes, full Org export parity, math/diagrams, local image/file links,
  Quick Look, synchronization, signing, and automatic updates.
